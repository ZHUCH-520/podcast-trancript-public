它会怎么做

你把材料交进来，
它按这六步处理。

每一步都能回头核对。原始音频和粗转录会留着，名字查不到也不会硬猜。

01 / 收材料

先确认材料

链接、音频、视频或现成转录都可以。你只要说明要中文、英文还是双语。

02 / 存原稿

单独保存这一期

每期用一个文件夹，原始音频和粗转录留着，方便回头核对。

03 / 转文字

转成文字

先检查电脑，再把模型选择、下载大小和保存位置告诉你。你同意后才准备本地转写。

04 / 查名字

查人名，切长稿

从节目页核对嘉宾和术语，再用随 skill 提供的脚本无损切开长稿。

05 / 整理

一段段整理

补标点、分说话人、修明显错字。不会为了好看把观点删掉。

06 / 导出

合并后再检查

检查开头结尾、重复、漏段和格式，生成 Markdown 和 HTML。

它最在意什么

好读，也得像原来
那个人在说话。

口头表达可以整理，观点和语气要留下。拿不准的地方会标出来，交给你确认。

01 · 不缺段

不漏内容

观点、例子和限定条件都要留下。摘要可以有，但不能顶替逐字稿。

02 · 不乱猜

人名别猜

能查到就核对，查不到就用中性标签，留给你确认。

03 · 像本人

保留说话方式

有用的停顿、幽默和口头习惯会保留，只清理明显的转写噪音。

04 · 能直接用

文件拿来就能用

最后给你 Markdown 和 HTML，也会检查漏段、重复和说话人格式。

第一次处理音视频

先看准备方案，
再决定下不下载。

它会先检查电脑，看看适合哪种转写方式。模型、大小和保存位置都会列清楚，得到你的同意才开始。

small · 先跑起来

下载小、速度快。适合先试一集，或配置普通的电脑。人名、口音和嘈杂录音可能要多改几处。

turbo · 比较均衡

新一些的 Apple Silicon Mac 会优先推荐这一档；合适的 Windows 或 Linux 显卡也可以用。

large-v3 · 更看重效果

适合人名多、口音重或录音质量一般的内容。下载最大，也更吃时间和内存。

Apple Silicon Mac 使用 MLX Whisper；Intel Mac、Windows 和 Linux 使用 faster-whisper。

已经有粗转录？直接交给它就行，不用安装 Whisper，也不用下载模型。

常见问题

装之前，
可能还想问这些。

模型怎么选、文件放哪里、认不认得说话人，都放在这里。

音频会被上传吗？

默认不会。本地转写工具可用时，音频留在本机。需要云端服务时，会先说明服务和要发送的数据。

small 会不会影响转写效果？

会有一些影响，尤其是人名、口音重或背景声多的时候。它的好处是下载小、速度快，适合先试一集；需要更稳时可以选 turbo 或 large-v3。

模型保存在哪里？

放在系统的用户缓存目录，不会放进节目文件夹或 skill 文件夹。下载前会显示具体位置。

我已经有粗转录，还要下载模型吗？

不用。它会保留粗稿，直接切成长段落继续核对和整理。

它总能认出所有说话人吗？

不能保证。可以选择安装本地说话人分离，它只会给出 SPEAKER_00 这样的编号，不是真实姓名。节目页能确认名字时就写名字，确认不了就用 Speaker A 或说话人 A，留给你复核。

它会绕过付费墙或受保护媒体吗？

不会。遇到登录、付费、DRM 或平台保护时，它会停下来，请你提供合法取得的音频或文稿。

完成后会自动发布吗？

不会。它只生成本地 Markdown 和 HTML。是否上传，由你决定。
